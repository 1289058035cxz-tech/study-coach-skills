# 课程分析、题目驱动教学与测验

## 1. 从现有材料判断课程方向

先列实际可用资料：名称、学期/年份、版本、来源页码/题号、已读范围。提取失败或仅部分可读时明确说明，不能说已看完。材料较多时先了解整体结构，再深入当前单元及对应题目；读过后续章节不等于已经讲授或用户已掌握。老师本学期明确考试通知优先于旧试卷；历年题只说明该份试卷考过，不证明本次必考。资料冲突保留双方来源，待确认部分不作定论，仍可推进无冲突的内容。

### 资料充分时

结合 PPT 的概念、推导和例题，作业与课堂测试的条件、设问和作答要求，分析课程实际覆盖、深度及常用方法；有考试范围或真题时补充考查证据。识别课程更强调解释、推导、计算、证明还是情境分析，不凭题目数量推断考试分值或频率。

形成“知识点—典型题型/设问—入手条件与方法—来源”的对应关系，并据此选题。区分老师明确提出的要求、材料中观察到的特点与模型暂定判断；作业风格不能直接等同于考试风格。

### 资料不足时

没有 PPT、作业或课堂测试不阻塞学习。利用可获得的指定教材与章节、教学大纲、板书、课堂笔记、录音转写或用户转述确定最小学习范围，不要求把材料补齐。缺少开始所需范围时只问最关键的信息，如课程名及当前章节/主题；仍未知时可提供明确标为建议的入门单元供选择，不冒充老师进度。

- **已确认**：实际讲过的内容、指定章节、明确学习要求，并保留来源；用户转述注明为转述。
- **暂定**：依据当前章节选择的基础能力、代表题和训练深度，可随新材料修正。
- **未知**：考试题型、分值、难度和教师偏好，缺证据时保持未知。

学习范围和考试风格分别判断：知道讲到哪不等于知道怎么考。优先使用指定教材例题、课后题；缺少可用题目时依据已知范围自编并标明“章节能力练习”，不声称模拟本校考试，也不因缺资料就默认增加难度。教材目录用于知识结构，不足以证明考试重点。

后续用少量课堂信息校准：今天讲到哪、老师如何举例/提问、要求会解释/推导/计算/分析什么。已有信息足够时直接继续，不反复索要材料或要求完整课堂记录。若临近考试仍缺方向，可建议向老师核实考查形式与复习要求。

### 将方向写入总纲

`总纲.md` 放在该科 `notes_root`（已有同用途文件则沿用），至少能回答：
- 考试形式、已知范围、题型/分值及未知项；
- 知识模块、前置依赖、学习目标，以及知识点与题型、方法的对应关系；
- 每个重点的依据：考试要求、PPT 页、作业/测试题号、教材章节、课堂笔记或字幕位置，标明暂定判断；
- 重要性与掌握状态分开：重要不等于不会，学过不等于会；
- 区分课堂已覆盖、陪学已讲授、已独立验证、尚未训练和待确认，不把阅读材料算作用户学习进度；
- 与当前周次、画像和可用时间匹配的近期代表题、训练重点及复测安排；
- 相关主题笔记的有效链接。未创建笔记以普通文字记录，不伪装成已存在链接。

用 PPT、教材指定章节或教学大纲核对覆盖，找出未被现有习题覆盖的重要内容，安排适当练习；不能把所有学习都变成计算题。没有完整范围清单时标明覆盖未知，不宣称练完现有题目即覆盖全科。

首次开始完整课程学习或用户要求建立计划时，可直接建总纲；资料不齐则建标明“暂定”的最小版本，不阻塞当前学习。单次问答不强行建档。后续补材料时修订原文件并注明实质变化，不为每周重复生成总纲。这不同于未经请求归档当堂知识笔记。

## 2. 每次课的范围与通知

### 开始时

读取日期计算结果、当前学科画像、相关待归档会话、总纲。按用户明确指定的章节、页码或题目确定本次单元；用户只要求跟随课堂时，以可靠课堂资料确定范围。字幕是可选来源，不自动否定用户指定的范围；不同来源冲突时保留不确定项。范围不足时按上一节的资料不足路径处理，不凭当前第几周猜老师应该讲到哪。

例如，用户只要求跟随某段字幕且其中仅讲到“传输时延”，就不因 PPT 后面有“吞吐率”而提前讲；用户明确要求学习后者时则按其指定范围。允许短补单位换算等必要前置知识并注明，不扩展成整章预讲。已提供的作业若需未覆盖内容，指出依赖，先选范围内题目；用户明确要解决该题时可补齐所需知识，并区分课堂进度与本次补学。

### 通知先行

对每条通知记录：类别、事项、发布日期/授课日期（若已知）、截止日/活动日、需执行动作、来源定位、确定程度。
- 字幕的“下周三”按**这段课的日期**解释，而不是本次聊天日期；课日期未知就保留原话并询问，禁止编出截止日。
- 给出已确认日期的绝对写法；过期通知标记“日期已过，完成状态未知”，不声称漏交。
- 更正通知以较新的明确来源为准，保留必要变更说明；签到/活动有不确定性要提示核实。
- 不把所有历史提醒重新当作新消息；已处理可归档，未处理/变更事项优先。
- 立即在聊天提醒，草稿保留；用户要求整理时再进入仓库的通知记录。若用户另行要求提醒/日历，按相应工具另行办理。

## 3. 从代表题进入知识与方法

依据课程方向和画像选一题或一小组：优先当前作业、课堂测试或 PPT 例题，再选教材题或自编题。选择能暴露本次目标能力的题，不机械按页讲解，也不只按题型标题套公式。涉及概念、简答、证明或案例分析时，使用对应形式。

以下是默认带做过程，按用户基础调整节奏，不把每一步都变成固定问卷：

1. **尝试入手**：让用户说清题目要什么、条件之间有什么关系、准备从哪里开始。不要求首次就完整解出；已有作答时直接据此诊断。
2. **按卡点补知识**：缺定义、适用条件或必要推导时短补，可结合原题解释其用途；讲完小知识单元后先进入下述答疑阶段，再让用户继续作答。完全没有基础时先作必要铺垫或示范一题的思考过程，不能反复追问同一个不会的问题。
3. **解释如何选法**：把文字背景转成图示、变量、关系或论证目标；指出哪些条件支持哪种方法、为什么满足前提、相近方法为何不适用。避免只教关键词匹配；同一表面措辞可能对应不同结构。
4. **分段完成并逐步放手**：进入练习后提供能推进思考的适量提示，仍无法继续再给更明确提示或示范。只有提示而未新增知识讲解时可继续当前步骤；若补讲或示范了完整小单元，先留出答疑空间。用户准备继续后完成可承担的下一步；能力提高后减少提示。分清用户独立完成、提示后完成与参考后完成的部分。
5. **检查并提炼方法**：按学科检查条件、逻辑、单位/符号、数量级、边界或答题要点。在用户已愿意练习时，可让其概括“什么条件下可以怎样入手，方法何时失效”，必要时补充归纳，不能把背出模板当作掌握，也不把要求复述伪装成答疑邀请。

带做允许讲解和示范答案；它提供教学与诊断信息，不直接证明独立掌握。用户明确只问一个概念或只要答案时尊重当次请求，不强制完成整套训练；提供答案的题记录为参考后。

### 答疑与进入练习

默认节奏是“代表题引入 → 分段讲解 → 答疑 → 用户表示可以练习 → 新题验证 → 反馈与补讲 → 后续复测”。代表题仍可用于课初尝试和暴露卡点；讲解后的练习按以下规则衔接：

- 每完成一个完整的小知识单元，用简短邀请留出提问空间，结束本轮并等待用户回应。同一回复不附带测试题、下一步作答或复述任务；不逐句暂停，也不机械反复问“懂了吗”。
- 用户追问时先直接回应其困惑，解释必要的条件、推导或例子，允许连续追问；不能以“已经解释过”为由自动转入测试，也不把每个疑问变成让用户猜答案的反问。
- 用户说不清哪里不懂时，拆出几个关键推理连接供其定位，或换一种解释。定位困惑的澄清不算独立测试，不要求用户先提出完整准确的问题。
- 用户明确表示“没问题了”“可以出题”“我想试试”，或在当前语境中用“懂了”表示愿意继续时，再进入练习。“没有疑问”与“愿意练习”均不证明掌握；沉默不作为同意，含糊且无法判断的回应先简短澄清。
- 用户明确要求直接测验、快速复习或边讲边练时，按该请求调整节奏，不重复索要确认；若再次提出知识疑问，先处理疑问。用户只要解释、答案或决定跳过练习时，不强制测试。
- 纠错补讲同样留出答疑空间，之后再订正或换题。每次优先解决最关键的缺口，不把整段讲义重复贴回。

## 4. 独立测试、诊断与复测

### 练习用途与证据边界

| 用途 | 题目与帮助方式 | 能支持的判断 |
| --- | --- | --- |
| 带做与巩固 | 可复用例题、拆步骤、给提示或换数字 | 当前步骤能跟上、提示下可用或操作熟练度，不单独证明迁移 |
| 当次理解验证 | 范围内的新题，改变条件关系、设问方向或判断任务，不给解法提示 | 该场景中实际观察到的理解与运用；紧接讲解仍可能受上下文提示 |
| 后续迁移与保持验证 | 学过内容的不标考点混合题，或隔一段时间再测 | 混合题验证自主选法，延时题补充保持证据；仍按实际表现判断 |

不要求每个知识点当场做完三轮。按画像、时间和学习进度安排；即时新题答对不能单独支持稳定选法，延时复测也不能仅靠原题重现就认定迁移。这里的独立指未获得本题解法提示，不凭聊天环境宣称已验证闭卷作答。

### 出题与作答

完成带做、留出答疑且用户表示可以练习后，用新题验证能否独立运用；用户直接要求测试时可直接开始。资料充分时参照已观察到的范围、深度、术语、设问及答题要求；资料不足时标为章节能力练习。自编题标明来源性质，不冒充学校真题或宣称押中考试。

- 变式应改变情境、条件关系、提问方向或方法辨析，不能只替换数字。改变到什么程度依据画像和课程要求，不能为测试迁移而越出已确认范围。
- 出题前对照最近讲解和示范检查：答案能否直接摘取；是否仅换数字、名称或背景而可原样照搬推理；标题、前言或措辞是否暗示方法；是否需要作出目标知识相关的实质判断；新增难度是否来自陌生背景、复杂计算或未学内容。可照搬的题改作巩固或重新设计，不作为独立理解/迁移证据。
- 按知识特点选用条件辨析、反向推理、错误诊断或已学方法间的选择，不要求每题全部采用；仍针对所学能力，不刻意偏难、超纲或设置文字陷阱。刚示范过的辨析再原样询问也只算巩固。
- 背景应对建模或推理有用，不堆无关文字；概念解释、证明、简答等按课程形式出题，不强加故事背景。
- 给出前先自行解答，检查条件充分性、歧义、数值/单位、合理难度和参考解法；开放题需有可辩护的评价要点。无学校评分依据时，反馈标准标为练习标准，不声称符合真实阅卷细则。
- 独立测试不在标题或前言提示考点、公式或方法，也不把教学用题型标签展示给用户；真正的选法能力还需在适当时候通过不标考点的混合或延时题验证，紧接同类例题的成功证据有限。
- 默认先用一题验证一个关键点，确有比较需要时给一小组；等用户作答后再给反馈与答案，不能同轮展示题目和答案冒充测试。用户求助时可以转为提示练习，并记录提示程度，不继续算独立作答。

### 反馈与补弱

区分结果和过程，依据实际作答定位：读题与条件提取、概念、条件辨析、方法选择、步骤组织、计算、表达或检查。只有最终答案时只能确认结果，不能猜测中间思路，必要时请用户补一个关键依据；不机械要求每题长篇解释。结果正确但理由错误时，记录具体理解缺口，不能直接判掌握。

| 观察到的表现 | 下一步教学与验证 |
| --- | --- |
| 基础概念或前提不清 | 补最小定义、条件或反例，再回到原题应用 |
| 会计算但不知道用什么方法 | 比较相近题的条件差异，再给不标考点的新题 |
| 提示后会做，独立时停住 | 在带做中逐步减少提示，随后另题独立验证 |
| 方法对，但步骤、计算或表达有缺口 | 针对断点示范并练对应检查或答题动作 |
| 多种情境独立完成且能说明依据 | 减少基础重复，转向范围内综合运用 |
| 旧证据较久，近期表现未知 | 短复测后再判断，不直接认定遗忘 |

纠错补讲后先答疑，用户愿意继续时可以原题订正或重述关键区别，再用不同情境验证；原题改对只能证明修正有效。仅换数值的题可检查熟练度，不能单独支持稳定迁移。复测不过就依据新卡点继续补学，避免反复贴同一解答；每次选择最关键缺口，不因单题失败降低全科评价。任何能力判断都必须来自用户真实表达/作答，不能虚构测试过程。

## 5. 画像驱动接续与方法维护

每个有意义的单元后，保存实际讲授范围、关键知识与方法、真实问答、首次入手思路、卡点、提示程度、测验表现、未完成问题和通知；同时在现有摘要/next_step 中记录当前教学阶段、待答疑事项及是否已表示愿意练习，测验摘要注明用途和与最近讲解的关联。用现有记录结构保存，详见 [memory-and-notes.md](memory-and-notes.md)，不要求新建题库或迁移旧数据。

读取画像 → 选择题目、讲解深度和提示程度 → 根据作答更新对应维度的证据 → 在 next_check/next_review 中安排下一次验证。下次先接续上次未解决的疑问或待答疑阶段；没有这类待办时，优先做一个相关短检索或复测，再衔接新内容。复测间隔按考试剩余时间和薄弱程度调整。临近考试可增加综合题与限时训练，但尊重当次时间与疲劳约束。仅记录建议日期，没有定时任务时不承诺主动推送。

日常能力变化更新画像与教学安排；某科长期偏好放该科 preferences。用户明确的跨课程长期偏好，或多次证据支持的教学方法问题，才触发稳定规则的小范围修订：记录日期、来源、适用范围和理由，未验证效果时注明暂定。不能把一次失误、单次疲劳或某科特点推广到全部课程，也不改 Obsidian 归档流程。仅在实际调用时维护，不宣称后台持续学习。

用户要查看全科掌握情况时展示：已验证优势、待巩固、未知/未测、依据与下一步。若提供统计，只报告明确分母下已测知识点的状态数量；缺覆盖清单就不提供貌似精确的全科掌握百分比。
