# 持久记忆、画像与 Obsidian 写入约定

## 文件职责

以本 skill 根目录为基准：

```text
state/semester.json                       学期基准、时区、估计/确切终点、默认仓库根
state/subjects.json                       学科 ID/别名 → vault_path、notes_root、考试日期
state/subjects/<id>/profile.json          具体知识点的证据性画像（唯一权威画像）
state/subjects/<id>/sessions/<id>.json     会话草稿：核心内容、问答、测验、通知、归档状态
```

初次画像无知识点即“未知”，空记录不等于零分。不要为没学过的科目预生成能力结论。JSON 用 UTF-8；写入前读最新文件，保留不属于本次的字段，临时文件加原子替换。所有持久化状态改写均使用 `scripts/study_state.py` 的 `state_lock` 排他锁，锁内重读并合并；不能用旧副本覆盖最新证据。脚本的路由变更使用同一锁，手动状态改写也遵守该锁。

注册表项包含 `id`、`name`、`aliases`、`vault_path`、`notes_root`、`exam_date`、`exam_date_source`、`registered_on`、`source`。不要把未经用户确认的相似名称添加成别名。同科出现在多个仓库时由用户选择，不按最近打开猜测。

可按平台检查 Obsidian 注册文件：macOS 的 `~/Library/Application Support/obsidian/obsidian.json`、Windows 的 `%APPDATA%/obsidian/obsidian.json`、Linux 的 `${XDG_CONFIG_HOME:-~/.config}/obsidian/obsidian.json`，只读 `vaults[*].path`；没有该文件时继续使用已登记路径/用户路径，不以此认定所有笔记不存在。新文件夹可作为 Obsidian 仓库打开，但创建文件夹并不意味着应用已经打开或注册它。

首次使用先按 [setup.md](setup.md) 初始化；不把示例配置作为真实学期。

### 工具用法

将 `SKILL_ROOT` 替换为本 skill 的绝对路径；命令参数均正确加引号：

```sh
python3 "SKILL_ROOT/scripts/study_state.py" status
python3 "SKILL_ROOT/scripts/study_state.py" status --subject "计算机网络"
python3 "SKILL_ROOT/scripts/study_state.py" register --name "某学科" --vault "/绝对路径/某学科"
python3 "SKILL_ROOT/scripts/study_state.py" register --name "某学科" --vault "/绝对路径/综合仓库" --notes-root "/绝对路径/综合仓库/课程/某学科"
python3 "SKILL_ROOT/scripts/study_state.py" create-subject --name "某学科"
```

`register` 不创建或修改现有仓库内容；子目录必须已存在且在仓库内。`create-subject` 不覆盖已有同名目录；已存在时先检查，属于该科才改用 `register`。更换已登记路径需在核实用户意图后使用 `register ... --replace`。`--state-dir` 用于测试/迁移，`status --today YYYY-MM-DD` 仅用于明确的历史查询或测试，正常启动不要硬编码今天。

## 能力画像

`profile.json` 的基本结构：

```json
{
  "subject_id": "由注册表生成的ID",
  "subject_name": "实际学科",
  "updated_on": null,
  "preferences": [],
  "coverage": {"last_session": null, "classroom_boundary": null, "taught_topics": []},
  "topics": [],
  "next_review": []
}
```

每个 `topics` 条目至少记录：
- `id`、`name`、`category`，必要时前置知识点 ID；
- `dimensions`：适用于该科的各维度状态，可包括读题与条件提取、概念理解、条件辨析、方法选择、推导/解题、表达与检查、迁移，不必每科启用同一组；新增维度随真实证据补充，历史缺项视为未测；
- `status`：未知 / 初步理解 / 提示下可用 / 可独立使用 / 稳定迁移；
- `confidence`：低/中/高，是证据可信度而非答对概率；
- `evidence`：日期、session ID、item ID、scenario ID、完成方式（独立/提示后/参考后/自述/未知）、表现摘要、支持/反驳哪项判断；
- `misconceptions`、`next_check`、`last_checked_on`、`review_due`（可以未知）。

判断规则：
- 用户问得多可能是深入探究，不直接推断基础差；未答或跳过不等于答错。
- 一次独立正确并说明依据可记录为该场景的独立使用，仍待不同场景验证。至少不同场景多次独立正确且能说明条件才能判“稳定迁移”；缺延时复测时说明长期保持尚未验证。
- 将完成方式与证据强度分开：未给本题提示也可能受紧接讲解的上下文影响。证据摘要注明带做巩固/当次理解验证/后续迁移或保持验证、与最近例题的关联及实际提示；照搬例题或只换数字不支持独立理解/迁移，即时新题成功只支持实际观察到的对应维度，不单独支持稳定选法。后续用已学内容的混合题或延时题补充证据，不凭聊天环境宣称已闭卷验证。
- “懂了”“没有疑问”可以表示愿意练习，能力上只算自述；未解决疑问不能因用户暂不追问就写成已理解。只有结果时不补写推理，正确结果伴随错误理由时记录具体缺口；提示后答对仍记录为提示下可用。
- 概念明确误解可立即记录当前缺口，但一次笔误不升级为长期弱点。证据冲突时保留新旧情境并安排验证，避免一题让等级来回跳变。
- 整体 topic 状态不能掩盖关键维度缺口：如基础计算独立，但条件辨析不会，不写“全面掌握”。
- 随时间变久降低证据新鲜度、安排复测，不直接宣判遗忘。没有新证据不只改更新时间。
- 自述偏好、暂时状态、可验证能力分开存；画像只留学习相关最小信息。

### 用画像调整教学与维护方法

将本次真实卡点、所需提示及下一步验证写入现有 evidence、misconceptions、next_check 和 next_review，不另建一套能力状态。选择题目、讲解深度与提示程度时读取这些证据；带做后成功不能覆盖独立测试暴露的缺口。整体会做与具体维度分开，未观察到的推理不补写为事实。

长期教学偏好记录在该科 preferences 中，注明日期、用户表达或多次证据来源、适用范围、调整理由，以及是明确偏好还是待验证假设。一次疲劳只作为当次约束。能力变化通常不改 skill 规则；用户明确的跨课程长期偏好或反复出现的方法问题才支持小范围修改稳定教学规则，并简短告知实际变化。保留旧记录及来源，不因本次方法升级重置或批量重判历史画像。

## 会话草稿：在正式整理前保存什么

会话 ID 用当地日期加时间/短随机后缀避免同日冲突。结构建议：

```json
{
  "id": "唯一会话ID",
  "subject_id": "学科ID",
  "started_on": "实际日期",
  "source_materials": [],
  "scope": {"covered": [], "excluded": [], "source": null},
  "items": [],
  "next_step": null,
  "archive_status": "pending"
}
```

每个 `items` 项含 `id`、`type`（knowledge/qa/quiz/notice）、`topic`、`source_locator`、`summary`、`archive_status`、`archived_to`。按类型补：
- `knowledge`：实际讲授的关键定义、推导链、条件、例子，以及条件如何支持选法、易混方法的区别和检查动作；不能只存标题，否则换对话无法整理。
- `qa`：问题要点、当时的困惑/错误假设、最终澄清、仍未解决处。
- `quiz`：可重建的题目条件、用户真实作答摘要、提示程度、关键步骤/错误、正确思路摘要、scenario ID；未作答明确标注，不填虚构答案。摘要区分示范/带做、独立测试、订正或复测，记录首次入手思路（未表达则未知）、具体卡点、实际给过的关键提示及后续验证动作；标清原题出处或自编性质。同题多次尝试共用 scenario ID，换数值不包装成独立迁移证据。
- `notice`：事项、原始时间描述、授课日期、解析后的绝对日期、动作、完成状态与来源。

不复制整段聊天或整份受版权保护资料；记录本次整理所需的最小充分内容。大公式或关键数值要保留到可复核的程度，不用“同上/见聊天”代替。草稿可分次补充、修正，确认已有条目 ID 后更新而不是重复追加。画像引用对应 item ID，支持以后纠错。

在 `quiz` 摘要中按实际情况补充练习用途、是否紧接同类讲解、是否复用示范结构、用户独立完成的部分及仍待验证的理解；未知就留未知。在 `next_step` 中记录当前阶段（讲解/答疑/待练习/待作答/待复测等）、未解决疑问及用户是否已表示愿意练习，相关澄清保留在 `qa` 中。跨对话先接续未完成答疑，不默认跳到新题；用户明确选择暂缓的问题保留待处理，不冒充已解决。使用现有字段，不新建另一套能力等级或批量改写旧记录。

source_materials 与 scope 保留已知范围的来源、读取范围及暂定判断，考试风格未知就写未知；不要把材料已读、课堂已讲、陪学已讲和独立验证混为一谈。上述补充优先使用已有摘要和证据字段，只在实际新记录中按需补充，不要求迁移旧会话。解题方法与卡点随现有正式整理流程进入对应主题笔记，不改变下述归档触发条件和写入步骤。

按单元检查点写盘；写失败明确说尚未持久化并保留可复制摘要。下次跨对话先读待归档项，不要求用户重新贴所有问答。用户明确要求不保存本次时尊重要求，不暗中生成画像证据。

## 正式整理：先知识分类，后保留课次来源

触发：“整理笔记”“把今天内容写进 Obsidian”“给我一个笔记.md”等明确请求。若用户要求**只导出、不写库**，只生成所需文件并保留待归档状态，不把导出误报为已写库。

默认范围为本次内容，加上与本次相关的历史未归档项；不同主题旧草稿提示仍待整理，不静默丢弃或混入。明确限定“只整理 A”时只处理 A，其他项继续 pending。

### 目录与内容

先读该科已有结构和目标笔记；没有结构时采用少量有内容的文件：
- `总纲.md`：课程范围与进度，不堆长问答；
- `知识点/<实际类别>/<主题>.md`：核心知识、条件、推导、个人问答与易错；
- 有真实练习时可用 `题型与练习/<题型>.md`；
- 有通知时才建 `课程事务.md`；
- `学习索引.md`：真实笔记链接及主要待复习主题，已有索引则复用。

不机械创建所有目录，不为每次课堂另建一套重复知识。课次/日期/PPT 页码/字幕位置保留在来源字段或文末；同一主题跨多堂课增量合并。问答与测验优先回到其知识主题；不能强制都塞进“第 N 讲”。

一篇主题笔记通常包含：高密度结论、核心概念及边界、必要推导/方法、用户本次真实困惑与澄清、代表性练习及表现、易错检查、下一次自测、来源与关联。按现有掌握程度省略已熟悉的基础冗余，不能省掉对当前用户至关重要的推理断点。参考答案与用户作答显式区分；尚未解决的问题不写成结论。

### 写入与验收

1. 汇总本次请求覆盖的 item ID，列出拟写目标；目录含用户文件时先读后合并，不整库重写。
2. 查重并确定分类，保留现有有效内容及用户措辞；新认知冲突要核实或保留待确认，不凭模型自信删除旧内容。
3. 写入 Markdown，采用现有 YAML/标签风格、Obsidian `[[链接]]` 和数学公式。链接必须有实际目标；未学主题只记待学。
4. 验证目标路径在该科 `notes_root` 内、写入内容可读、公式/代码围栏成对、索引与链接存在、没有遗失本次重要问答/测验/通知。必要时更新总纲的实际课堂覆盖。
5. 只有对应内容已写入并检查通过，才为该 item 记录 `archive_status: archived`、`archived_to`（相对 notes_root 的路径）和 `archived_on`。其余项保持 pending，混合状态的会话记 partial。重复执行先核对已归档目标，不重复追加。
6. 多文件操作部分失败时只标成功项，不能整会话标完成；保留剩余草稿并报告失败。不要自动删除原始材料与未归档证据。

完成后给简短可核实摘要，而不是重复贴整库内容。长期画像以 skill 的 profile.json 为准；若用户要可见的画像笔记，可以在仓库生成注明日期的摘要，避免两套独立状态。
