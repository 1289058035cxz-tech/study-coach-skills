# 学科资料、共享状态与接续

## 依赖定位与读取

本 skill 根目录记为 `REVIEW_ROOT`。优先在同级目录定位 `semester-study-coach`，记为 `COACH_ROOT`；安装位置变化时从当前可用技能目录定位该名称，不依赖工作目录或硬编码用户主目录。

开始或恢复某学科测评时：
1. 阅读 `COACH_ROOT/SKILL.md` 的路由和画像约定，以及 `COACH_ROOT/references/memory-and-notes.md`。本 skill 明确规定的题量、课程题型优先级、反馈形式及知识笔记/教练索引分工优先；其余共享状态、画像判据和归档触发、写入校验约定沿用原文。尤其不要把原文要求保留的个人测验表现直接写入用户的知识笔记。
2. 读取 `COACH_ROOT/state/semester.json`、`state/subjects.json`，运行 `python3 "COACH_ROOT/scripts/study_state.py" status`。用本次实际日期和用户时区，不用 skill 创建日期。仅在与安排有关时简短提示周次/倒计时，不重复显示面板。
3. 根据明确学科匹配注册表，验证 `vault_path`、`notes_root`。路径失效或多候选时询问需修复的具体信息；不默认最近打开的仓库。
4. 读取该科 `state/subjects/<id>/profile.json`、相关未归档 `sessions/`、独立教练索引（若有）、真实总纲和当前课堂边界；通过索引及定向搜索读取范围内的笔记正文、易错点和旧题。保留已读文件/小节，未读部分不能宣称已覆盖。
5. 若继续未完测验，先恢复原题、已出题组、已提交答案、提示影响与待覆盖清单，再决定下一步。不重新生成同名试卷覆盖旧题。

路由登记复用现有 `study_state.py register`，参数与校验见原 skill 的参考文件。只有路径或学科关联明确时登记，不因“开始复习”自动创建一个空仓库来代替缺失笔记。

依赖尚未初始化时读取 `COACH_ROOT/references/setup.md`，按用户提供的信息配置，不照搬示例校历。用户暂不配置时仍可基于已有笔记进行不保存的练习。

依赖缺失时说明不能接入共享画像；若已有用户指定的笔记或提供的内容，可继续当前对话的暂定练习，不建立替代画像、虚构路径或声称已保存。只有无法确定学科/范围或无可用材料时才询问缺失信息。不因创建或维护此 skill 去启动真实测验、登记示例学科或修改真实画像。

## 唯一状态来源

学科路径仍以 `COACH_ROOT/state/subjects.json` 为准；能力状态仍以原 `profile.json` 为唯一权威。新 skill 不创建自己的 `state/`、第二套能力等级或独立错题数据库。

每次测评在原学科 `sessions/` 保存一个会话，兼容既有 `source_materials`、`scope`、`items`、`next_step` 和归档状态。优先使用已有字段；需要接续的附加信息可放在该会话的可选 `review` 字段，不迁移旧记录。

`review` 可按需要保存：
- `mode`：复习训练或直接测验；`phase`：知识诊断/混合测验/反馈/复测。
- `assessment_id`、`current_group`：稳定试卷标识和当前分组。
- `coverage`：知识点 ID/名称、来源、目标维度、对应题目或小问、已安排/已出题/已作答/已有证据状态。
- `priming`：哪些知识在前置回顾、反馈或提示中被提醒，以及影响的待答题。
- 用户约定的时长、范围和题量，以及本轮诊断/混合题/回顾/复测已用预算；未指定的内容保留为估计或未知。
- 课程题型规定的来源、适用范围、允许形式、已明确的比例/分区及确定性，或未发现规定时采用的题型组合；不把历史卷样式写成未经确认的硬性要求。

题目保存为 `items` 中的 quiz 条目，沿用原有 ID 和来源格式，至少足以重建：
- 完整题目条件、选项、图表必要信息、设问和题目所属组；资料过长时可引用同一会话目录内实际保存的支持文件，不能只写“见聊天”。
- `scenario ID`、自编性质、与旧题有何实质变化、内部考点映射和参考答案/评价要点；这些记录用于恢复与批改，作答前不通过预览或附件主动展示。
- 用户原始答案或忠实摘要、首次思路（未表达则未知）、信心标记（若有）、提交状态、已给提示及受影响小问。
- 批改结果、错误机制、订正与复测关系、下一次验证动作。

没有作答的题记“待作答”；参考答案与用户答案分栏，不得把内部解答当用户表现。只生成试卷时可以保存试卷草稿，不能给画像增加成功/失败证据。

## 画像更新与写入安全

遵守原 skill 的证据格式及等级判据，复用知识点 ID。每条证据链接真实 session/item/scenario，并注明日期、独立/提示后/参考后、测验阶段、是否刚复习过、支持的具体维度和限制。

同题的订正共用 scenario ID；仅换数值不累计成新的迁移证据。新情境可有新 ID，同时保留来源关系。多次独立正确且能解释条件才支持稳定迁移；未做延时复测则说明长期保持未验证。近期未测只安排检查，不自动判遗忘。

每完成一个有意义单元保存检查点；中断时尽可能保留已出题和待答进度。写入前重读最新文件，保留无关字段。共享写入使用原脚本同一 `state/.write.lock`（使用原脚本的跨平台 `state_lock` 排他锁），在锁内读取、合并和通过临时文件原子替换；不能仅靠当前聊天内串行操作规避其他任务的并发写入。

先保存会话证据，再更新引用该证据的画像；检查引用存在。部分写入失败只报告实际成功部分，保留待更新内容，下一次按 item ID 去重接续，不覆盖整个历史文件。没有新证据不只刷新画像时间。

用户明确要求不保存本次时不写会话、画像或笔记。日常测评不更改两个 skill 的稳定规则；跨科偏好和单科偏好沿用原 skill 的维护边界。

## 正式整理：知识笔记与教练索引分开

只有用户明确要求整理/写入 Obsidian 时，读取原 `memory-and-notes.md` 的归档流程，复用其查重、合并、路径校验、原子写入及归档标记；本节负责内容分工。用户只要求导出知识笔记时只导出知识内容，不写库、不附内部记录，也不改变正式归档状态。

### 用户阅读的知识笔记

按已有知识主题归档：概念与专业定义、适用条件、知识联系、推导与方法、通用易混点、易错检查、必要的代表性例题及完整规范答案。真实追问可以提炼成知识解释，个人错误可以提炼成条件提醒，保留教材/PPT 等知识来源。

不加入用户原始答案、某次答错经历、得分、日期化的作答流水、提示次数、掌握等级、复测结果或个人待办；不为每轮测验建立一篇用户复习笔记，也不将个人过程藏在笔记的 YAML、折叠块或附录中。例：“结论成立前须检查条件 A”可进入笔记；“某日第 2 题在提示后才补上 A”进入教练记录。代表题为知识说明服务，不复制整套卷或个人答题过程。

用户的总纲/学习索引只保留知识导航、课程范围与教材/课堂来源，个人薄弱清单和测验进度放独立教练索引；不把教练记录嵌入知识正文或知识导航。

### 供助手接续的独立教练索引

先查该科是否已有独立的内部记录区并复用；没有时在 `notes_root` 下使用 `_教练记录/复习索引.md`，有实际内容才创建。此文件是 Obsidian 中独立可访问的普通笔记，用途是助手接续，不声称它被隐藏或仅助手有权限。不得使用正常知识笔记作为内部记录区。

按知识点保留最小充分的定位信息：
- 现有 topic ID、关联知识笔记的有效链接；
- 具体薄弱维度/误区、最近证据日期及独立/提示后/参考后等条件；
- 来源 session/item/scenario ID 和可访问的真实记录位置，必要时保存简短表现摘要；
- 当前测验组、待答/待测范围、下一次验证动作；
- 生成/同步日期及“以共享 profile.json 和 sessions 为准”的说明。

个人原始作答、完整题目、提示与复测细节继续保存在共享 `sessions/`，索引负责定位，无需再复制一份题库。确有接续需要的补充记录放同一教练目录并从索引链接；所有 Markdown 链接须有真实目标，不能用 Obsidian 双链假装 JSON 记录是库内笔记。路径以当前注册表核实，不在公共 skill 文件中写个人路径。

`profile.json` 仍是唯一权威能力画像；教练索引是可重新生成的导航与摘要，不独立评级，不建立另一套状态。索引与画像不一致时回查真实证据，依据最新共享记录修正索引；不能用旧索引覆盖画像。用户编辑的索引内容先核实来源，不自动当成作答证据。

### 写入与归档检查

1. 整理前为本次 item 分配知识笔记、教练索引或两者的目标；知识内容进入主题笔记，个人表现进入教练记录。没有必要提炼为知识的 quiz 只需在教练索引中定位其会话证据。
2. 先读后合并，保留已有有效知识；核对公式、代码围栏、路径与链接，确认知识笔记没有混入个人作答记录，教练索引能定位真实证据。
3. 相应目标均写入并检查成功后，才按原格式记录该 item 的 `archive_status`、`archived_to` 和 `archived_on`；需要多个目标时逐项核对。部分失败只标成功项，保留剩余待归档内容，不把整会话标完成。
4. 旧笔记已混入个人记录时，仅在本次明确整理或修订范围内提炼知识并迁出个人记录；先保存可追溯的教练记录再移除正文中的过程，不扩展为整库历史迁移。

仅结束练习时保存会话草稿和画像；教练索引在下次获准写库时同步，不因本规则自动修改真实笔记。用户明确不保存时三个位置都不写。完成后分别简短报告知识笔记与教练索引的实际位置及未完成项，不把内部证据表整份贴入知识笔记或完成消息，不声称后台监测。
