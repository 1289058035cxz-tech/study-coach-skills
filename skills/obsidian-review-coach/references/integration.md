# 学科资料、共享状态与接续

## 依赖定位与读取

本 skill 根目录记为 `REVIEW_ROOT`。优先在同级目录定位 `semester-study-coach`，记为 `COACH_ROOT`；安装位置变化时从当前可用技能目录定位该名称，不依赖工作目录或硬编码用户主目录。

开始或恢复某学科测评时：
1. 阅读 `COACH_ROOT/SKILL.md` 的路由和画像约定，以及 `COACH_ROOT/references/memory-and-notes.md`。本 skill 明确规定的混合测评节奏优先；其余共享状态、画像判据和归档约定沿用原文。
2. 读取 `COACH_ROOT/state/semester.json`、`state/subjects.json`，运行 `python3 "COACH_ROOT/scripts/study_state.py" status`。用本次实际日期和用户时区，不用 skill 创建日期。仅在与安排有关时简短提示周次/倒计时，不重复显示面板。
3. 根据明确学科匹配注册表，验证 `vault_path`、`notes_root`。路径失效或多候选时询问需修复的具体信息；不默认最近打开的仓库。
4. 读取该科 `state/subjects/<id>/profile.json`、相关未归档 `sessions/`、真实总纲和当前课堂边界；通过索引及定向搜索读取范围内的笔记正文、易错点和旧题。保留已读文件/小节，未读部分不能宣称已覆盖。
5. 若继续未完测验，先恢复原题、已出题组、已提交答案、提示影响与待覆盖清单，再决定下一步。不重新生成同名试卷覆盖旧题。

路由登记复用现有 `study_state.py register`，参数与校验见原 skill 的参考文件。只有路径或学科关联明确时登记，不因“开始复习”自动创建一个空仓库来代替缺失笔记。

依赖尚未初始化时读取 `COACH_ROOT/references/setup.md`，按用户提供的信息配置，不照搬示例校历。用户暂不配置时仍可基于已有笔记进行不保存的练习。

依赖缺失时说明不能接入共享画像；若已有用户指定的笔记或提供的内容，可继续当前对话的暂定练习，不建立替代画像、虚构路径或声称已保存。只有无法确定学科/范围或无可用材料时才询问缺失信息。不因创建或维护此 skill 去启动真实测验、登记示例学科或修改真实画像。

## 唯一状态来源

学科路径仍以 `COACH_ROOT/state/subjects.json` 为准；能力状态仍以原 `profile.json` 为唯一权威。新 skill 不创建自己的 `state/`、第二套能力等级或独立错题数据库。

每次测评在原学科 `sessions/` 保存一个会话，兼容既有 `source_materials`、`scope`、`items`、`next_step` 和归档状态。优先使用已有字段；需要接续的附加信息可放在该会话的可选 `review` 字段，不迁移旧记录。

`review` 可按需要保存：
- `mode`：复习训练或直接测验；`phase`：知识诊断/混合测验/反馈/复测。
- `assessment_id`、`current_group`：稳定试卷标识和当前分组。
- `coverage`：知识点 ID/名称、来源、目标维度、对应题目或小问、已安排/已出题/已作答/已有证据状态。
- `priming`：哪些知识在前置回顾、反馈或提示中被提醒，以及影响的待答题。
- 用户约定的时长、范围和题量；未指定的内容保留为估计或未知。

题目保存为 `items` 中的 quiz 条目，沿用原有 ID 和来源格式，至少足以重建：
- 完整题目条件、选项、图表必要信息、设问和题目所属组；资料过长时可引用同一会话目录内实际保存的支持文件，不能只写“见聊天”。
- `scenario ID`、自编性质、与旧题有何实质变化、内部考点映射和参考答案/评价要点；这些记录用于恢复与批改，作答前不通过预览或附件主动展示。
- 用户原始答案或忠实摘要、首次思路（未表达则未知）、信心标记（若有）、提交状态、已给提示及受影响小问。
- 批改结果、错误机制、订正与复测关系、下一次验证动作。

没有作答的题记“待作答”；参考答案与用户答案分栏，不得把内部解答当用户表现。只生成试卷时可以保存试卷草稿，不能给画像增加成功/失败证据。

## 画像更新与写入安全

遵守原 skill 的证据格式及等级判据，复用知识点 ID。每条证据链接真实 session/item/scenario，并注明日期、独立/提示后/参考后、测验阶段、是否刚复习过、支持的具体维度和限制。

同题的订正共用 scenario ID；仅换数值不累计成新的迁移证据。新情境可有新 ID，同时保留来源关系。多次独立正确且能解释条件才支持稳定迁移；未做延时复测则说明长期保持未验证。近期未测只安排检查，不自动判遗忘。

每完成一个有意义单元保存检查点；中断时尽可能保留已出题和待答进度。写入前重读最新文件，保留无关字段。共享写入使用原脚本同一 `state/.write.lock`（使用原脚本的跨平台 `state_lock` 排他锁），在锁内读取、合并和通过临时文件原子替换；不能仅靠当前聊天内串行操作规避其他任务的并发写入。

先保存会话证据，再更新引用该证据的画像；检查引用存在。部分写入失败只报告实际成功部分，保留待更新内容，下一次按 item ID 去重接续，不覆盖整个历史文件。没有新证据不只刷新画像时间。

用户明确要求不保存本次时不写会话、画像或笔记。日常测评不更改两个 skill 的稳定规则；跨科偏好和单科偏好沿用原 skill 的维护边界。

## 正式整理

只有用户明确要求整理/写入 Obsidian 时，读取并执行原 `memory-and-notes.md` 的正式归档流程。按知识主题合并真实误区、纠正依据和代表性练习，不把整套测试机械复制到每个主题。先查已有笔记、保留有效内容，再校验公式与链接；成功后才标记相应条目已归档。

仅结束练习时保存草稿和画像即可。导出试卷或反馈不等于写库；用户只要导出时不改变正式归档状态。报告实际保存位置与未完成项，不声称后台监测或未来不读文件也能记忆。
