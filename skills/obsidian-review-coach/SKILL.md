# 笔记复习与混合测评

目标：通过陌生情境里的真实作答，区分知识熟悉、条件理解、独立选法和迁移运用。默认中文。测验日期以实际调用时的日期和用户时区为准。

“混合”指知识点交错、题型混合、难度顺序打乱，题目仍须条件清楚、逻辑严密。默认主线：读取笔记与画像 → 范围和覆盖清单 → 知识诊断 → 混合测验 → 诊断反馈 → 换情境复测 → 更新证据。

## 与现有学习流程协作

本 skill 负责复习测评。复用 `semester-study-coach` 的学科注册表、会话草稿和唯一能力画像，不建立第二套学科状态，不修改其稳定教学规则。

开始或恢复测评前，读取 [references/integration.md](references/integration.md)，定位依赖、读取相应学科材料并恢复进度。出题与批改前读取 [references/assessment.md](references/assessment.md)。正式整理沿用原 skill 的归档流程。

本流程的默认组织方式是整套或分组测验、提交后批改；适用于这里的混合测评，不机械套用课程带学的逐题提示流程。用户指定只做其中一部分、直接测验或随时求助时，尊重当次请求，并记录证据条件。

## 1. 明确范围并读取材料

- 优先用用户指定的学科、范围、时间和题量；缺少学科或开始所需范围时只询问必要信息。不要因仅登记一科就默认归入它。
- 读取对应笔记、易错点、相关历史题目及画像。先看索引和总纲再读所需正文，不扫描整盘或无关学科。标题清单不能代替阅读内容。
- 确定知识点及适用条件、易混方法、知识联系、历史薄弱点和未测能力。每个点保留笔记标题/小节等来源定位；个人错误与一般易错提醒分开。
- 资料冲突先核实或标注待确认，不以疑似错误笔记为唯一评分依据。笔记不足时明确已读范围和缺口；可基于用户提供内容做暂定练习，不虚构已有画像或完整课程覆盖。
- 简短说明本次学科、范围、模式、预计用时/分组和资料限制，随后进入练习。已有信息足够时不重复问配置，不输出整份考点提示清单。

## 2. 建立内部覆盖清单

为约定范围建立“知识点 → 来源 → 考查维度 → 题号/小问 → 覆盖状态”。兼顾已知易错点、近期未验证点及已有独立证据的点，不把试卷缩成纯错题集。

“全部知识点”仅指本次约定且能从资料核实的范围。每点必须实际参与作答或推理；题干提及不算考查。混合测验自身须覆盖约定范围，不能用前置知识问答抵扣混合卷中的遗漏。

范围超过合理题量或时间时拆为多组交错试卷，保留整体覆盖清单，明确当前组和待覆盖部分，不静默缩减范围。区分已安排、已出题、已作答、已有有效证据；出完题不等于完成测评。

## 3. 知识诊断

默认先做一小组基于笔记的理解题，以条件判断、相近情境辨析、反例、错误推理定位、改变条件后的结论为主。必要定义可少量检查，不逐条背诵笔记标题。

等待作答后再反馈；追问以澄清实际思路为目的。基础缺口明显时补最小解释，不反复盘问。此轮用来发现卡点，后续混合卷不能复制这些问题或只换数值。

默认模式为“复习训练”：知识诊断及必要补讲后再测验，记录哪些知识刚被提示或复习。后续即使独立完成，也注明是复习后的表现，不解释成未经提醒的长期保持。

用户要求摸底、检查遗忘或不预习时，采用“直接测验”：先做混合卷，提交后再进行知识追问和补讲。用户可跳过前置阶段；不强制解释整套模式菜单。

## 4. 混合测验

- 自编新情境，实质改变条件关系、信息呈现、提问方向或任务目标；对照已读例题与历史题，不能只换名称、数字和故事外壳。
- 背景陌生且有推理作用，复杂性来自条件提取、关系建立、约束比较或多阶段判断。提供作答所需的陌生背景知识，保持学科范围内可解；不靠长篇无关材料或超纲知识制造难度。
- 打散知识点、题型和难度，不按章节分块或从易到难排列。题型根据学科选择，包含适宜的选择、填空、简答、计算、证明、纠错或案例分析；不机械凑齐全部类型。
- 兼顾单点辨析与跨知识点综合，不要求每题覆盖全部知识点。简单题也可置于新情境中；复杂背景不等于每题都要高难度。
- 题目前后不提供考点、公式、方法、难度标签、答案或评分关键词；允许必要的题型说明、单位、图示、作答要求和分值。
- 出题前自行求解并按 assessment.md 校验，固定当前试卷的参考答案和评价要点后再呈现。自编内容标注为复习练习，不冒充学校真题或押题。
- 默认一次呈现整套卷或一个完整混合分组，等提交后批改。分组须有明确边界，避免聊天长度或疲劳破坏作答；不要未经请求改成每题讲完再出下一题。

## 5. 作答、诊断与复测

用户可附关键依据和可选信心标记“确定/不确定/猜测”。不把自信当掌握证据，也不要求每道简单题写冗长推理。

求助时立即转为适量提示，记录受影响的小问、提示内容和时点；提供答案后标“参考后”。未作答/跳过记为未测，不记为错误。反馈若提示了其他待答题的方法，相关题也需标注影响。

提交后分开评价结果与过程，检查条件提取、概念边界、方法选择、推导/计算、表达检查和迁移。只有答案时不编造中间思路；正确但理由不明时补问关键依据，区分原始作答与追问后的证据。

诊断先定位最关键缺口，再补最小解释，用新情境的另一题验证同一能力。原题订正、刚看过同类解法后的成功和不同情境独立完成分别记录；不把换数值或同题重做累计成多个迁移证据。后续混合或延时复测进一步检查保持，间隔按实际时间和薄弱程度调整。

## 6. 记录与结束

按 integration.md 在单元检查点保存试卷进度、真实作答、提示和证据，更新现有画像。没有真实作答就不生成能力结论；一次错误不降低全科评价，一次成功不判稳定掌握。

结束时简明报告：本次实际覆盖、有独立证据的能力、暴露的缺口、证据不足/未测内容、下一次验证。可附练习分数，但不能替代逐点诊断；无明确覆盖分母不提供全科掌握百分比。

用户要求整理时才正式写入 Obsidian，并沿用现有分类和双链；仅结束练习时保存会话草稿。用户要求不保存则只在当前对话反馈，不暗中写盘。所有维护发生在调用时，不自动创建定时任务或声称后台监测。
